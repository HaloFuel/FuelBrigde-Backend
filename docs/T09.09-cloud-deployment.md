# T09.09 — Arquitectura Cloud y Despliegue Azure

## 1. Objetivo

Definir una arquitectura de despliegue propuesta en Microsoft Azure para el backend FuelBridge, considerando su separación en servicios independientes y la comunicación REST entre componentes.

## 2. Componentes de la arquitectura

| Componente | Tecnología propuesta | Función |
|---|---|---|
| Aplicaciones backend | Azure Container Apps | Ejecutar los ocho servicios Java |
| Registro de imágenes | Azure Container Registry | Almacenar las imágenes Docker |
| Base de datos | Azure Database for MySQL Flexible Server | Administrar los ocho esquemas de datos |
| Automatización | GitHub Actions | Construcción, publicación y despliegue |
| Frontend | Hosting por definir | Interfaz Angular para los usuarios |

## 3. Servicios contemplados

La arquitectura incluye FuelBridge Platform, Catalog, Notification, Reporting, Equipment, Inventory, Payment y Fulfillment.

FuelBridge Platform conserva los módulos IAM y Ordering. Los demás servicios se consideran aplicaciones independientes y mantienen comunicación REST conforme a las dependencias del sistema.

## 4. Consideraciones de seguridad

- Almacenar contraseñas y secretos mediante mecanismos seguros, no dentro del repositorio.
- Utilizar HTTPS para las comunicaciones externas.
- Restringir el acceso a MySQL mediante conectividad privada.
- Configurar autenticación y autorización JWT en los servicios correspondientes.
- Aplicar permisos mínimos a las identidades utilizadas en el despliegue.

## 5. Estrategia de despliegue propuesta

1. Ejecutar las pruebas automatizadas.
2. Construir las imágenes Docker.
3. Publicar las imágenes en Azure Container Registry.
4. Configurar Azure Container Apps.
5. Conectar los servicios a MySQL.
6. Verificar la comunicación REST entre componentes.
7. Registrar las evidencias de despliegue.

## 6. Evidencias disponibles

- Diagrama `docs/diagrams/fuelbridge-azure-deployment.puml`.
- Vista previa generada correctamente mediante PlantUML.
- Configuración local existente mediante Docker Compose.

La infraestructura cloud descrita corresponde a una propuesta técnica. No se afirma que los recursos Azure estén aprovisionados ni que los servicios se encuentren desplegados en la nube.
